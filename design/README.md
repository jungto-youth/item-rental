# 디자인 시안 — 물품 대여

`web-lit/src`의 12개 화면을 HTML + Tailwind CSS로 옮긴 **1차 디자인 시안**입니다.
빌드 없이 브라우저에서 바로 열 수 있고, 390 / 768 / 1280에서 확인했습니다.

## 파일

| 파일 | 화면 |
| --- | --- |
| `index.html` | 물품 현황 `/` |
| `item-detail.html` | 물품 상세 `/items/:id` |
| `item-form.html` | 물품 등록 `/items/new` · 수정 `/items/:id/edit` |
| `states.html` | 로딩·빈·검색 없음·오류·대여 불가·완료 상태 |
| `login.html` | 로그인 (전체 화면) |
| `signup-profile.html` | 최초 로그인 후 이름·연락처 등록 (전체 화면) |
| `mypage.html` | 내 정보 — 표시·수정 모드 |
| `my-rentals.html` | 대여 내역 — 현재 대여·이력·반납·취소 |
| `admin-reservations.html` | 대여 관리 — 상태 필터·반납 처리 |
| `admin-members.html` | 회원 관리 — 역할·탈퇴·허용 이메일 |
| `policy.html` | 이용약관 · 개인정보 처리방침 |
| `not-found.html` | 404 |
| `build.ts` | 공통 조각 빌드 — `partials/`를 각 페이지 마커에 채웁니다 |
| `partials/head.html` | 공통 `<head>` — meta·폰트·테마 토큰 (화면별 `<title>`은 페이지가 소유) |
| `partials/footer.html` | 공통 푸터 원본 (한 벌만 둡니다) |
| `preview.js` | 12개 페이지 공통 미리보기 바 (화면 선택·역할 전환) |
| `assets/components.css` | 여러 화면이 같이 쓰는 규칙 — 기본 리셋·필터 칩·상태 배지·인풋 유효성 |
| `assets/logo.png` | 실제 앱 로고 |
| `assets/page-layout.css` | 공통 2열 셸 — 왼쪽 주 컨텐츠 · 오른쪽 보조 패널 |

```bash
open design/index.html
open design/item-detail.html
open design/item-form.html
open design/states.html
open design/login.html
open design/signup-profile.html
open design/mypage.html
open design/my-rentals.html
open design/admin-reservations.html
open design/admin-members.html
open design/policy.html
open design/not-found.html
```

Tailwind v4 브라우저 CDN, Google Fonts(Noto Sans KR), Unsplash 사진을 사용하므로
**인터넷이 필요합니다.** 배포용이 아니라 리뷰용 시안입니다.

## 공통 조각

푸터처럼 여러 화면에 같은 마크업이 들어가는 부분은 `partials/`에 **한 벌만** 두고,
각 페이지의 마커 사이에 채웁니다. 페이지에는 마크업이 남지 않습니다.

| 조각 | 담는 것 | 남는 것 |
| --- | --- | --- |
| `head` | meta·폰트·Tailwind CDN·테마 토큰 | `<title>`, `page-layout.css` 링크, 화면별 `<style>` |
| `footer` | `<footer>` 전체 | 없음 (변형은 마커 인자) |

```html
<!-- @begin head -->
<!-- @end head -->

<!-- @begin footer -->
<!-- @end footer -->
```

CSS도 같은 원칙입니다. 여러 화면이 똑같이 쓰는 규칙(기본 리셋, 필터 칩, 상태 배지, 인풋 유효성)은
`assets/components.css`에만 두고, 화면별 레이아웃(`.home-layout`, `.policy-layout`)만 각 페이지 `<style>`에 남깁니다.

마커 이름 뒤에 붙인 토큰은 partial의 `{{class}}` 자리로 갑니다. 화면별 변형은 이 한 줄로 끝납니다.

```html
<!-- @begin footer -->                  → <footer class="border-t border-line">
<!-- @begin footer bg-surface -->       → <footer class="border-t border-line bg-surface">
<!-- @begin footer mt-10 -->            → <footer class="border-t border-line mt-10">
```

```bash
node design/build.ts          # 마커 사이를 채운다
node design/build.ts --check  # 최신인지 확인 (npm run check 에 포함)
```

- 마커 **안쪽은 생성 영역**입니다. 직접 고치면 다음 빌드에 덮이므로 `partials/footer.html`을 고칩니다.
- 마커 쌍은 지우지 마세요. 빌더가 이 자리를 찾아 다시 채우며, 그래서 몇 번을 실행해도 같은 결과가 나옵니다.
- 결과는 순수 정적 HTML이라 `file://`로 그대로 열립니다. (`fetch` 주입은 `file://`에서 차단되고, ES 모듈도 막히므로 로더는 JS가 아니라 빌드입니다.)
- 마커는 HTML 주석이라 브라우저가 무시합니다. `<component id="footer">` 같은 비표준 태그를 쓰면 빌드를 빠뜨렸을 때 푸터가 **소리 없이** 사라집니다.
- 로그인·프로필 등록의 작은 정책 링크 줄과 `states.html`의 시안 목차는 다른 조각이라 공유하지 않습니다.

## 미리보기 조작

- 모든 시안 상단의 **디자인 미리보기** 바에서 화면을 선택하고 `회원` / `관리자` 역할을 전환합니다.
  - 화면 선택: 물품 현황·상세·등록/수정, 계정, 대여·관리, 정책, 상태, 404.
  - 관리자: 홈·상세·상태의 관리자 전용 UI(회원 관리 메뉴, 물품 등록 버튼, 모바일 FAB, 상세 수정)가 나타납니다.
  - 관리자 전용 화면(물품 등록·수정, 대여 관리, 회원 관리)은 `회원` 역할에서 앱과 같이 **관리자 권한 안내**가 뜹니다. 안내의 `관리자로 보기`를 누르거나 바에서 `관리자`를 고르면 화면이 보입니다.
- 홈의 검색과 상태 필터가 실제 카드에 적용되고, 결과가 없으면 빈 상태가 나옵니다.
- 상단 계정 아바타를 누르면 `내 정보` · `로그아웃` 메뉴가 열립니다.
- 상세 화면의 **썸네일**을 누르면 큰 사진과 순번이 바뀝니다.
- 상세 화면의 **수량 스테퍼**는 1~2개 사이에서 동작합니다.
- `대여하기`는 정적 목업이라 페이지를 새로고침하지 않습니다.
- 목록의 모든 카드는 같은 상세 시안(`4인용 텐트`)으로 연결됩니다.
- `states.html`은 정적 상태 갤러리입니다. 빈 목록의 문구·등록 버튼은 회원/관리자에 따라 바뀝니다.
- 로그인 버튼 → 프로필 등록 → 내 정보까지 이어집니다.
  - `login.html?error=denied`(또는 `deactivated`, `unavailable`)로 로그인 오류를 확인합니다.
  - `mypage.html?nophone=1`로 연락처 미등록 상태를 확인합니다.
  - 프로필 저장·내 정보 수정은 실제로 입력값을 검증하고 화면에 반영합니다.
- 대여 내역: 반납/취소 → 확인 모달 → 이력으로 이동. 모두 반납하면 빈 상태와 이력이 열립니다.
- 대여 관리: 상태 필터, 반납 처리 시 배지와 칩 개수가 함께 갱신됩니다.
- 회원 관리: 검색, 역할 변경(마지막 관리자 보호), 탈퇴·등록 정보 삭제,
  허용 이메일 추가/제거(목록 아래 접이식 섹션).
- 물품 등록·수정은 화면 선택에서 `물품 등록` / `물품 수정`을 고릅니다.
  - 저장 검증, 태그 추가·삭제, 사진 추가·삭제, 이탈·삭제 확인 모달이 동작합니다.
  - 사진 업로드/촬영은 예시 이미지를 넣는 시뮬레이션이에요.
- 정책은 화면 선택 또는 페이지 상단 탭으로 이용약관/개인정보를 오갑니다. 목차 앵커와 모바일 표 스크롤이 있습니다.

## 이번 시안에서 정한 것

### 1. 홈 — 카탈로그처럼 스캔되게

- 페이지 제목 아래에 `함께 쓰는 물품과 대여 상태를 확인해요.` 한 줄을 두어 맥락을 만듭니다.
  물품 종 수는 화면마다 달라지므로 부제에 숫자를 쓰지 않고, 상태 필터 칩이 현재 값을 보여줍니다.
- 데스크톱은 **왼쪽 주 컨텐츠(검색 + 상태 필터 + 물품 그리드) · 오른쪽 보조 패널(대여 안내)** 2열입니다.
  오른쪽 패널은 스크롤해도 따라오도록 sticky로 둡니다.
- 검색은 데스크톱 400px, 태블릿 560px로 제한합니다.
- 상태 필터 칩은 알약형 칩으로, 화면 폭에 맞춰 내용 폭만큼
  가로로 정렬하고 좁으면 다음 줄로 넘깁니다. (대여 안내 카드는 모바일에서 숨깁니다.)
- 카드는 `사진 → 이름 → 위치 → 대여 가능 수량` 순서를 유지합니다.
  - 모바일 3열에서는 분류를 숨기고 **위치만** 남겨 `7층 비…` 같은 잘림을 없앴습니다.
  - 제목은 390px에서 한 줄에 들어오도록 짧게 다듬었습니다.
- 10건 + `더보기`, 사진 없는 물품의 폴백을 실제 화면에 포함했습니다.

### 2. 상세 — 대여 신청을 ‘신청서’처럼

- 데스크톱은 갤러리 1.05fr + 정보 0.95fr 2열, 1024px 이하에서 1열입니다.
- 갤러리는 큰 사진 + 3장 썸네일 + `1 / 3` 카운터. 썸네일 클릭으로 전환됩니다.
- 스펙은 카드 대신 **헤어라인 표**로 두어 정보가 먼저 읽히게 했습니다.
- 이 화면의 유일한 주 액션은 `대여하기`입니다. `수정`은 secondary로 내렸습니다.
- 대여 폼은 점선 구분선을 넣어 **대여 신청서**처럼 보이게 했습니다.
  점선 아래에 수량·메모·버튼, 아래에 “신청하면 바로 대여 중” 안내를 둡니다.
- 하단에 `캠핑 물품 더 보기` 4개를 두어 대여 후 다음 행동을 만듭니다.

### 3. 상태 화면

`states.html`에 다음을 정리했습니다.

- 물품 현황: 로딩(스켈레톤), 빈 목록, 검색 결과 없음, 오류, 더보기 실패
- 물품 상세: 로딩, 오류, 대여 완료, 대여 불가(재고 없음·로그인 필요·소모품·대여 종료)
- 빈 목록은 회원에게 “관리자가 등록하면 표시돼요”, 관리자에게는 등록 버튼을 보여줍니다.
- 로딩은 실제 카드·상세 레이아웃과 같은 골격을 써서 화면이 튀지 않게 했습니다.
- 오류는 원인과 다음 행동(다시 시도)을 함께 말하고, 상세 오류에는 목록으로 돌아가는 길을 남깁니다.

### 4. 계정 흐름

- **로그인**: 헤더 없는 전체 화면. 로고 → `물품 대여` → 한 줄 소개 순서로
  브랜드를 먼저 보여주고, 주 액션은 Google 버튼 하나만 둡니다.
- **프로필 등록**: 로그인에 이어지는 온보딩 2단계라 같은 전체 화면을 씁니다.
  셸 헤더·푸터 대신 `반가워요` 한 줄과 계정 확인 행에 집중하고 이름·연락처를 받습니다.
  두 필드 모두 필수이며, 비어 있으면 필드별 오류를 보여줍니다.
  헤더의 계정 메뉴가 없으므로 폼 아래에 `다른 계정으로 로그인` 출구를 둡니다.
- **내 정보**: 계정 카드에서 표시/수정 모드를 전환합니다. 저장하면 이름·연락처와
  헤더의 이니셜·이름이 함께 갱신되고 `저장했어요`가 남습니다.
- 연락처가 없으면 `mypage.html?nophone=1`에서 상단 배너와 `미등록` 상태를 보여주고,
  배너의 `연락처 등록하기`가 바로 수정 모드로 들어갑니다.
- 세 화면 모두 같은 토큰·카드·버튼·인풋을 쓰고, 로그인과 프로필 등록은 셸 헤더·푸터를 숨깁니다.

### 5. 대여·관리

- **대여 내역**: 현재 대여 중을 먼저 보여주고, 지난 이력은 접이식으로 둡니다.
  현재 대여 카드는 잉크색 테두리로 강조하고, 반납·취소는 확인 모달을 거칩니다.
  모두 반납하면 빈 상태와 이력이 함께 열립니다.
- **대여 관리**: 상태 칩(전체·대여 중·반납 완료·취소)으로 목록을 걸러 봅니다.
  대여 중 카드만 진한 테두리와 `반납` 버튼을 갖고, 회원 연락처는 바로 전화할 수 있는
  `tel:` 링크입니다. 회원이 직접 반납한 건은 회수 확인 경고를 남깁니다.
- **회원 관리**: 회원 목록과 검색을 먼저 두고, 허용 이메일은 목록 아래
  접이식 보조 섹션으로 내립니다. 역할 select는 행마다 바로 두고,
  마지막 관리자는 역할 변경·탈퇴가 막히고, 탈퇴 회원은 대여 중인 물품이 있으면
  등록 정보 삭제가 비활성화됩니다. 탈퇴·삭제는 확인 모달을 거치고, 삭제 후에는
  이름·연락처가 익명화됩니다.
- 관리자 화면은 상단 메뉴가 `물품 현황 · 대여 관리 · 회원 관리`로 바뀌고,
  회원 화면은 `물품 현황 · 대여 기록`을 유지합니다.
- 상태 배지는 점과 텍스트를 흐름 안에 두고, 점 6px·간격 6px·좌우 패딩 10px로
  묶음이 가운데 오도록 맞췄습니다.

### 6. 물품 등록·수정

- 720px 한 열에 `기본 정보` · `분류·상태` · `재고·사진` 세 카드로 나눴습니다.
  등록과 수정은 같은 폼을 쓰고, 제목·초기값·삭제/공개 보기만 달라집니다.
- 카테고리는 태그 에디터(엔터로 추가, ×로 제거), 구분·상태는 선택 칩으로 둡니다.
  소모품을 고르면 수리중 수량 필드가 숨습니다.
- 사진은 3칸 슬롯입니다. 첫 사진에 `대표` 배지를 붙이고, 추가/삭제는 저장 전까지
  스테이징된다는 문구를 남깁니다. 추가는 사진 촬영/업로드 선택 모달로 이어집니다.
- 저장 시 이름·수량·수리중 수량을 검증하고, 오류는 폼 상단 배너로 모아 보여줍니다.
  실제 앱은 저장 후 목록으로 돌아가지만, 시안은 `등록했어요` 상태를 보여주려고 남습니다.
- 취소(미저장 변경)와 삭제는 확인 모달을 거칩니다.

### 7. 정책·404

- 정책은 왼쪽 **본문 + 오른쪽 320px 목차** 2열로 다른 화면과 같은 1280 셸을 씁니다. 모바일은 목차가 숨고 본문만 남습니다.
  문서 가독성을 위해 본문 행간만 1.75로 넓혔습니다.
- 실제 `policy.ts`의 이용약관·개인정보 처리방침 문구를 사용했고, 표는 모바일에서
  가로 스크롤됩니다. 상단 탭으로 두 정책을 오갑니다.
- 404는 공개 헤더 아래 중앙에 두고, `물품 현황으로`·`이전으로` 두 출구만 남겼습니다.

### 8. 공통 2열 셸

- 목록·계정·관리 화면은 **왼쪽 주 컨텐츠 + 오른쪽 320px 보조 패널**로 통일했습니다.
  - 홈: 검색 + 상태 필터 + 물품 그리드 / 대여 안내
  - 대여 내역: 현재 대여 + 이력 / 반납 안내
  - 대여 관리: 상태 필터 + 목록 / 반납 처리 안내
  - 회원 관리: 회원 목록 + 허용 이메일 섹션 / 역할·마지막 관리자 안내
  - 내 정보: 계정 카드 / 대여 현황 + 연락처 안내
  - 물품 등록·수정: 폼 / 작성·사진 안내
- 오른쪽 패널은 1024px 이상에서 sticky로 따라오고, 모바일에서는 숨깁니다.
  목록 조작에 필요한 상태 필터는 모바일에서도 목록 위에 둡니다.
- **로그인·프로필 등록을 제외한 모든 화면** 하단에 공통 푸터(브랜드 한 줄 + 이용약관·개인정보처리방침)를 둡니다.
  두 온보딩 화면은 정책 링크만 작게 남깁니다.
  404는 흰 면(`bg-surface`), 그 외는 캔버스 바탕입니다.
  푸터는 `partials/footer.html`이 유일한 원본이고, 화면별 차이는 마커 인자(`bg-surface`, `mt-10`)로만 넘깁니다.
- 공통 규칙은 `assets/page-layout.css`의 `.page-split` · `.page-side`가 소유합니다.

### 9. 디자인 시스템 유지

- 기존 토큰을 그대로 Tailwind `@theme`로 옮겼습니다.
- 중립 회색 바탕 · 흰 카드 · 오렌지 포인트, 8px 그리드, 8/999 라운드.
- 카드·인풋에는 그림자를 쓰지 않고 1px 테두리로 구분합니다.
- 그림자는 FAB에만 사용합니다.
- `prefers-reduced-motion`을 존중합니다.

### 10. 채운 버튼의 대비 보정

기존 `--primary`(#ea580c)에 흰 글자를 얹으면 대비가 약 3.6:1입니다.
이 시안에서는 **채운 버튼 배경만** `--primary-strong`(#c2410c, 약 5.2:1)로 내리고,
hover는 `--primary-deep`(#9a3412)을 씁니다. 브랜드 오렌지는 점·배지·테두리·링크에 유지했습니다.

> 실제 앱에 반영할 때는 `tokens.css`에 `--primary-deep`을 추가할지 먼저 결정해야 합니다.
> 추가하지 않으면 hover를 `--primary-strong` 또는 `--ink-1`로 대체할 수 있습니다.

## 아직 시각만 구현된 것

정적 HTML 시안이라 API·세션·저장은 원래 범위 밖입니다. 화면 안에서 기대할 수 있는
동작 중 아직 연결되지 않은 것은 다음과 같습니다.

- 홈 `더보기`: 10건 샘플만 있고 다음 데이터를 불러오지 않습니다.
  칩 숫자(24/18/4/2)는 카탈로그 전체 기준이고, 화면에는 10건만 있습니다.
- 관리자 모드의 홈 카드: 실제 앱은 수정 폼으로 가지만 시안은 상세로 이동합니다.
- 상세 `대여하기`: 제출만 막아 두었고 실제 대여·성공 상태는 `states.html`에만 있습니다.
- 로그인: Google OAuth는 프로필 등록으로 이어지는 시뮬레이션이고, 실제 구글 이동·세션은 없습니다.
- 프로필 등록 → 내 정보: 입력값이 전달되지 않고 내 정보는 샘플 값을 보여줍니다.
- 대여 내역·관리자 화면: 화면 안에서만 상태가 바뀌고 새로고침하면 초기화됩니다.
- 물품 폼: 사진 업로드·촬영은 예시 이미지 시뮬레이션이고, 저장 후 목록 이동은 하지 않습니다.
  `공개 보기`는 항상 텐트 상세로 연결됩니다.
- `states.html`: 상태 갤러리라 버튼은 시각 전용입니다.
- 404 `이전으로`: 히스토리 없이 직접 열면 동작하지 않을 수 있습니다.
- 정책 목차: 앵커 이동은 되지만 현재 섹션 강조는 없습니다.
