# 검증과 운영

디자인 시스템은 만드는 순간보다 **유지하는 과정**에서 무너진다.
이 문서는 변경 전후를 확인하는 최소 절차다.

## 1. 시각 회귀

### 현재

- Playwright 기반 브라우저 테스트가 있다.
  - `npm run test:photos`
  - `npm run test:members`
  - `npm run test:profile`
  - `npm run test:visual` — 홈·상세·로그인·개발 로그인·관리자 회원 화면을 390/768/1280으로 비교
- 기준 이미지는 `web/tests/visual/baseline/`에 둔다.
- 실패 시 현재 화면은 `web/tests/visual/current/`에 저장된다. (gitignore)

```bash
npm run test:visual          # 기준선과 비교
npm run test:visual:update   # 의도한 변경이면 기준선 갱신
```

`test:visual`은 Vite 개발 서버를 띄우고 API를 고정 fixture로 대체하므로
D1·R2·구글 로그인 없이 실행된다. 기준선은 **같은 브라우저/OS**에서만 동일하게
렌더되므로 CI에서는 컨테이너 이미지를 고정한다.

### 확장 우선순위

1. 빈 목록·검색 결과 없음·오류 상태
2. 물품 등록 폼의 필드 오류·사진 0/3
3. 모달·카메라 권한 거부
4. 키보드 포커스 스냅샷

캡처 우선순위:

1. 홈 (사진 있음/없음, 필터, 빈 상태)
2. 물품 상세 (사진 있음/없음, 대여 가능/불가)
3. 물품 등록 폼 (기본/오류/사진 0장)
4. 로그인
5. 관리자 대여 기록·회원 관리

## 2. 접근성

기준: **WCAG 2.2 AA**

| 항목 | 기준 |
| --- | --- |
| 본문 텍스트 대비 | 4.5:1 이상 |
| 큰 텍스트 | 3:1 이상 |
| UI 경계·포커스 | 3:1 이상 |
| 포인터 타깃 | 최소 24×24 CSS px |
| 키보드 | 모든 주요 흐름 Tab/Shift+Tab으로 이동 |
| 포커스 | 항상 보이고, 가려지지 않음 |
| 이름·역할·상태 | 스크린리더로 읽힘 |
| 모션 | `prefers-reduced-motion` 존중 |

수동 체크:

- [ ] 키보드만으로 로그인 → 홈 → 상세 → 대여 → 반납
- [ ] 모달에서 Esc 닫기, 포커스 트랩, 닫은 뒤 포커스 복귀
- [ ] 오류 메시지가 `aria-live` 또는 `role="alert"`로 읽힘
- [ ] 이미지 대체 텍스트(장식이면 빈 alt)
- [ ] 표·목록의 헤더와 역할
- [ ] 200% 확대에서 레이아웃 깨짐 없음

자동화 후보:

```bash
npm i -D @axe-core/playwright
```

주요 화면 5개에 axe를 붙여 critical 위반 0을 목표로 한다.

참고: [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [WAI Quick Reference](https://www.w3.org/WAI/WCAG22/quickref/)

## 3. 사용성 테스트

5명 내외로 충분하다. 숫자보다 **막히는 지점**을 찾는 것이 목적이다.

### 과업

1. “4인용 텐트를 찾아서 2개를 빌려보세요.”
2. “내가 빌린 물품을 반납해보세요.”
3. “관리자로 새 물품을 등록해보세요.”

### 기록

| 항목 | 내용 |
| --- | --- |
| 성공 여부 | 도움 없이 완료했는가 |
| 소요 시간 | 과업 시작 → 완료 |
| 오류 | 잘못 누른 곳, 되돌아간 횟수 |
| 막힌 지점 | “여기서 뭘 눌러야 하죠?” |
| 만족도 | 1–7 (SEQ) |

관찰 포인트:

- “수정”이 버튼인지 라벨인지 바로 아는가
- 입력창이 입력 가능한 곳으로 보이는가
- 대여 가능 수량이 한눈에 읽히는가
- 빈 상태에서 다음 행동이 보이는가
- 모바일에서 필터·검색이 잘리지 않는가

## 4. 휴리스틱 리뷰

Nielsen의 10가지 휴리스틱, 특히 **#8 미학적·미니멀 디자인**으로 화면을 점검한다.

- 불필요한 정보·장식이 핵심 정보를 가리는가
- 필요한 신호(상태·조작·오류)를 지우지 않았는가
- 같은 모양이 다른 의미로 쓰이지 않는가
- 시스템 상태가 항상 보이는가
- 사용자가 실수를 되돌릴 수 있는가

참고: [NN/g — Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/)

## 6. 운영 규칙

- **소유자 1명** — 최종 판단 기준을 유지한다.
- **토큰 밖 값 금지** — 예외는 리뷰에서 설명한다.
- **변경 기록** — 토큰·컴포넌트 변경은 changelog에 남긴다.
- **폐기 절차** — 대체 컴포넌트와 마이그레이션 기간을 둔다.
- **문서는 코드 옆에** — `docs/design-system/`와 `tokens.css`를 함께 갱신한다.

## 7. CI 최소선

```bash
npm run check        # 타입
npm test             # 단위·통합
npm run build        # 번들
npm run test:visual  # 화면 회귀
```

여기에 axe 검사와 3 뷰포트 스냅샷을 더하면 “디자인이 깨졌는데 모르고 배포”하는 일을 크게 줄일 수 있다.
