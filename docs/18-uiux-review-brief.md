# 18 — UI/UX 검토용 화면 설명서

> 다른 LLM(또는 디자이너)에게 **현재 화면의 배치와 정보 구조**를 설명하고 리뷰를 받기 위한 문서.
> 스크린샷 없이도 레이아웃을 상상할 수 있도록 화면별 구조·상태·반응형 규칙을 서술한다.
> 기준 시점: 2026-11-05, 소스: `web/src` (SolidJS SPA + Tailwind v4).

## 사용법

1. 이 문서 전체를 리뷰어 LLM에 붙여넣는다.
2. 맨 아래 **“8. 리뷰 요청 프롬프트”** 를 이어서 붙여넣는다.
3. 필요하면 “모바일만 집중”, “관리자 화면만”, “정보 구조만”처럼 범위를 좁힌다.

- 정토회 청년 대상 **공용 물품 대여 서비스**. Google OAuth(`@jungto.org` 또는 관리자가 허용한 이메일)로만 로그인.

- 모바일 사용 비중이 높다고 가정한 모바일 우선 설계. 한국어 UI, 라이트 모드만 지원.

## 1. 공통 디자인 시스템

### 1.1 룩 & 무드

- 따뜻한 중립 회색 바탕 + 흰 카드 + 잉크색 텍스트 + **오렌지 포인트**.
- 장식용 그림자·그라데이션·큰 색면 없음. 카드·입력은 1px 테두리로 구분.
- 그림자는 떠 있는 층(계정 메뉴, 모달, 모바일 FAB)에만.
- 라운드: 컨트롤/카드 **8px**, 칩·배지·아바타 **999px(pill)** 두 종류만.
- 간격은 **2px 기반 눈금**(2/4/6/8/12/16/20/24/32/40/48/56). 간격에 10px·18px 같은 값은 쓰지 않음.
- 글자: **10/12/14/16/20/24/28/32/40/48/56/64px** 눈금만. 기본은 14px(캡션·라벨·버튼·문서 본문) / 16px(화면 본문·입력) / 20px(섹션 제목) / 24px(페이지 제목), 칩·배지는 12px. 10px 미만 없음.

### 1.2 색 토큰

| 역할 | 값 | 쓰임 |
| --- | --- | --- |
| `ink-1` | `#111827` | 제목·본문 |
| `ink-2` | `#4b5563` | 보조 설명·라벨 |
| `ink-3` | `#9ca3af` | 비활성·아이콘 |
| `bg` | `#f6f7f9` | 페이지 바탕 |
| `surface` | `#ffffff` | 카드·입력 |
| `surface-muted` | `#f3f4f6` | 사진 자리·호버·보조 면 |
| `line` / `line-strong` | `#e5e7eb` / `#d1d5db` | 헤어라인 / 입력 경계 |
| `primary` / `primary-strong` / `primary-deep` / `primary-soft` | `#ea580c` / `#c2410c` / `#9a3412` / `#fff1e8` | 액션·선택·강조 면 |
| `warning` / `warning-soft` | `#b45309` / `#fffbeb` | 수리 중·승인 대기 |
| `danger` / `danger-soft` | `#dc2626` / `#fef2f2` | 오류·삭제·거절 |

- `primary`는 주 액션과 선택 상태에만, `danger`는 오류와 파괴적 행동에만.
- 상태 배지: 점(dot) + 텍스트 조합. 대여 가능/예약 가능=오렌지, 수리 중/승인 대기=앰버, 기한 지남/거절=빨강, 나머지=회색.

### 1.3 레이아웃 토큰

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `layout-max` | 1280px | 헤더·본문·푸터 공통 최대 폭 |
| `layout-form` | 720px | 폼·계정 카드(정의만, 실제 화면은 2열 셸 안에서 사용) |
| `layout-onboarding` | 400px | 로그인·프로필 등록(실제 카드 폭 340px) |
| `layout-doc` | 1280px | 정책 문서 셸 |
| 2열 셸 | `minmax(0,1fr) 320px` | 1024px 이상에서만 우측 보조 패널 표시 |
| sticky | `top: 96px` | 데스크톱 보조 패널 |

### 1.4 반응형 기준

Tailwind 기본 브레이크포인트를 쓴다.

- `sm` 640px / `md` 768px / `lg` 1024px / `xl` 1280px
- 본문 패딩: 전 화면 20px (좌우·상하 동일).
- **1024px 미만에서는 우측 보조 패널을 전부 숨긴다.** 안내 문구는 사라지고, 관리자 물품 등록 진입은 홈의 FAB가 대신한다.
- 헤더: 모바일 56px, `md`부터 64px. 모바일은 로고만, `lg`부터 서비스 축약명 표시.
- 물품 그리드: 모바일 2열 → `sm` 3열 → `md` 4열 → `xl` 5열, 간격 8px.

### 1.5 앱 셸

```
┌──────────────────────────────────────────────┐
│ AppHeader (sticky, 56/64px)                  │
├──────────────────────────────────────────────┤
│ main (max 1280px, padding 20px)              │
│                                              │
├──────────────────────────────────────────────┤
│ AppFooter (로그인·프로필 등록 제외)           │
└──────────────────────────────────────────────┘
```

- **로그인(`/login`)과 프로필 등록(`/signup/profile`)만 헤더·푸터 없는 전체 화면**이다. 콘텐츠는 화면 중앙에 놓인 340px 폭 카드.
- 나머지 화면은 모두 헤더+본문+푸터.
- 푸터는 서비스명 + `이용약관 · 개인정보 처리방침`. 404만 흰 배경(`surface`), 나머지는 회색 바탕.
- 관리자이면서 홈(`/`)일 때만 **모바일 FAB**(오른쪽 아래 48px 원형, `+`, "물품 등록")가 뜬다. `lg` 이상에서는 숨고 우측 패널의 버튼을 쓴다.

### 1.6 헤더

**데스크톱**

```
[로고 28px] 청년 물품 대여   물품 현황  [대여 관리  회원 관리]  대여 내역        (아바타) 이름 ⌄
```

- 관리자에게만 `대여 관리`, `회원 관리`가 추가된다. `대여 내역`은 역할과 무관하게 항상 있다.
- 메뉴 글자 14px, 메뉴 사이 간격 16px. 현재 경로에 따라 메뉴 아래 2px 오렌지 밑줄 + 진한 글자.
- `물품 현황`은 `/`와 `/items/*`에서 활성.
- 오른쪽 계정 버튼: 이니셜 아바타(32px) + 이름(`md` 이상) + 화살표(`sm` 이상). 클릭하면 드롭다운(최소 176px, 14px, 16px 패딩): `내 정보`, `대여 내역`, `로그아웃`(빨강).
- 비로그인 상태에서는 오른쪽에 `로그인` 채운 버튼.

**모바일**

- 로고만 남고, 메뉴는 가로 스크롤 가능한 탭 줄(스크롤바 숨김). 계정은 이니셜 아바타만.
- 메뉴가 많아질 수 있어 이름·축약명은 숨긴다.

### 1.8 공통 상태 패턴

- **로딩**: 목록·카드형 화면은 실제와 같은 스켈레톤. 페이지 전환·세션 확인은 중앙 스피너.
- **빈 상태**: 항상 “왜 비었는지 + 다음 행동”을 함께 보여준다. (예: “등록된 물품이 없습니다” + “관리자가 물품을 등록하면 여기에 표시됩니다.”)
- **오류**: `다시 시도` 버튼을 함께 제공. 홈 목록은 오류 시 자동 무한 스크롤을 멈춘다.
- **성공/안내 메시지**: 화면 상단 한 줄. 성공은 체크 아이콘, 오류는 빨간 글자 + `role=alert`.
- **파괴적 확인**: 취소·탈퇴·삭제·나가기는 모두 모달 확인을 거친다.

## 2. 화면별 설명

### 2.1 `/login` — 로그인

**목적** 허용된 구글 계정으로 로그인. **접근** 공개. **셸** 헤더·푸터 없음.

**레이아웃 (모바일·데스크톱 동일)**

```
                ┌────────── 340px ──────────┐
                │          [로고]            │
                │   정토회 청년 물품 대여      │
                │   필요한 물건을 빌리고,      │
                │   다 쓰면 돌려주세요.        │
                │                            │
                │ ┌ 정토회 계정 안내 ───────┐ │
                │ │ @jungto.org 또는 허용 계정│ │
                │ └─────────────────────────┘ │
                │ [ G  Google로 계속하기 ]     │
                │ (오류 메시지)                │
                │ 처음 로그인하면 회원으로...   │
                │ ── 개발용 테스트 로그인 ──   │
                │ [접근 코드] [테스트 로그인]   │
                └────────────────────────────┘
                     이용약관 · 개인정보 처리방침
```

- 전체 화면 `min-height: 100dvh`, 중앙 정렬, 바깥 패딩 20px.
- 로고 40px(600px 이상 48px), 제목 24px, 태그라인 16px 회색.
- 계정 제한 안내는 얇은 테두리 카드, 14px.
- Google 버튼: 40px 높이, 14px 500, 좌우 16px, 흰 바탕 + 테두리, 18px 컬러 G 아이콘.
- 오류는 버튼 아래 빨간 14px 한 줄.
- 개발 서버에서만 `테스트 접근 코드` 입력 + `로컬 테스트 관리자 로그인` 폼이 점선 구분선 아래에 나타난다. 코드가 설정되지 않았으면 빨간 안내.
- 맨 아래 정책 링크 2개.

**검토 포인트** 로그인 화면에 정보가 많은 편(제한 안내 + 첫 로그인 안내 + 정책 + 개발 폼). 개발 폼은 운영에서 숨겨지지만, 일반 사용자에게 보이는 텍스트의 우선순위가 적절한지.

### 2.2 `/signup/profile` — 프로필 등록

**목적** 최초 로그인 후 대여에 필요한 이름·휴대폰·지부·지회·모둠 입력. **접근** 로그인. **셸** 헤더·푸터 없음.

**레이아웃**

```
              ┌────────── 340px ──────────┐
              │  연락처와 소속을 등록해 주세요 │  ← 이름이 이미 있으면
              │  (또는 "반가워요")           │
              │  물품을 빌리려면 ... 필요합니다│
              │ ┌ 로그인한 계정 ✓ email ──┐ │
              │ │ 이름 *                  │ │
              │ │ 휴대폰 번호 *            │ │
              │ │ [지부 *]                │ │
              │ │ [지회 *] [모둠 *]        │ │
              │ │              [저장]     │ │
              │ └─────────────────────────┘ │
              │ 저장하면 바로 물품을 둘러볼 수 │
              │ 다른 계정으로 로그인          │
              │ 이용약관 · 개인정보           │
              └────────────────────────────┘
```

- 중앙 340px, 세로 패딩 32px, `min-height: 100dvh`.
- 이름이 구글 계정에 있으면 제목이 `연락처와 소속을 등록해 주세요`, 없으면 `반가워요`로 바뀐다.
- 폼 카드는 흰 카드, 라벨 위·입력 아래. 지부를 먼저 고른다. 청년지부는 지회/모둠이 2열 select이고, 지회를 고르기 전에는 모둠이 비활성(`지회 먼저`). 대중지부는 지회/모둠을 2열 입력칸으로 직접 받는다.
- 이메일은 읽기 전용 회색 칩으로 상단에 표시(체크 아이콘).
- 저장 성공 시 `/mypage`로 이동. 오류는 폼 하단 빨간 줄.
- 하단에 “입력 정보는 대여 연락에만 사용”, “관리자 지정은 기존 관리자가” 안내와 정책 링크.

**검토 포인트** 온보딩인데 헤더가 없어 “지금 어디인지” 맥락이 약하다. 로고가 없고 제목만 있어 브랜드 연속성이 끊기는지.

### 2.3 `/` — 물품 현황 (홈)

**목적** 물품 검색·상태 필터·탐색. **접근** 로그인. **셸** 헤더+푸터, 관리자에게만 모바일 FAB.

**데스크톱 레이아웃 (1024px 이상)**

```
물품 현황
함께 쓰는 물품과 대여 상태를 확인합니다.
┌ 검색 400px ──────────────┐    ┌ 우측 320px (sticky) ─────────┐
│ 이름, 위치, 분류 검색     🔍 │    │ [물품 등록]  ← 관리자만       │
└──────────────────────────┘    │ ┌ 대여/관리자 안내 카드 ────┐ │
                                │ │ 제목 + 2줄 설명           │ │
                                │ │ [대여 관리] [대여 내역]    │ │
                                │ └──────────────────────────┘ │
[전체][대여 가능][예약 가능][대여 중][수리 중] │                              │
┌카드┐┌카드┐┌카드┐┌카드┐        └──────────────────────────────┘
│사진││사진││사진││사진│
│이름││이름││이름││이름│
│분류·위치│...
│● 대여 가능 2개│...
└────┘└────┘└────┘└────┘
```

- 바깥 그리드는 `1fr + 320px`. 검색은 왼쪽 위(최대 400px), 필터와 그리드는 그 아래, 우측 패널은 두 행에 걸쳐 sticky.
- 검색 입력: 40px 높이, 오른쪽 돋보기, 그 왼쪽 `✕`(검색어가 있을 때). 입력 즉시(250ms 디바운스) 검색. `Esc`로 지우기.
- 상태 필터 칩 5개: `전체 / 대여 가능 / 예약 가능 / 대여 중 / 수리 중`. URL 쿼리(`?q=&state=`)와 동기화되어 새로고침·뒤로가기에 유지.
- 카드 그리드: 데스크톱 4열(1280px 이상 5열), 카드 간격 8px.
- 카드 구성: 3:2 사진(없으면 회색 면+`사진 없음`) → 이름(2줄 말줄임) → `분류 · 위치`(모바일은 분류 숨김) → 상태 점+텍스트. 카드 전체가 링크.
- 관리자 홈: 카드 목록을 관리자 API에서 1000건까지 받아 클라이언트 필터. 우측에 `물품 등록` 버튼과 관리자 안내 카드.
- 회원 홈: 우측에 `대여 안내` 카드(승인 흐름 설명 + `대여 내역` 링크)만.
- 무한 스크롤: 10개씩, 목록 끝 600px 전에 자동 로드. 별도 `더보기` 버튼 없음. 실패 시 안내 + `다시 시도`.
- 검색 결과가 정확히 없고 의미상 비슷한 물품만 있으면 상단에 `비슷한 물품을 보여줍니다` 안내.
- 권한 거부로 리다이렉트되면 상단에 빨간 `관리자 권한이 필요합니다` 배너.

**모바일 레이아웃 (1024px 미만)**

```
물품 현황 / 부제
[검색 (전체 폭) 🔍]
[전체][대여 가능][예약 가능]...
┌카드┐┌카드┐
└────┘└────┘
... 무한 스크롤
                        (관리자면 + FAB)
```

- 우측 패널은 **완전히 숨김**. 대여 안내·관리자 안내가 사라진다.
- 검색은 전체 폭, 카드 2열, 카드 패딩 12px, 이름 14px.
- 관리자는 오른쪽 아래 48px FAB로만 물품 등록 가능.

**검토 포인트**

- 데스크톱에서 검색이 400px로 고정되어 왼쪽에 큰 여백이 생긴다. 필터·그리드는 전체 폭을 쓰는데 검색만 좁은 것이 어색하지 않은지.
- 우측 320px 패널이 “안내” 중심이라 정보 밀도가 낮다. 홈에서 꼭 필요한 정보인지.
- 모바일에서 대여 안내가 사라져 “승인제”를 처음 쓰는 회원이 흐름을 모를 수 있다. 상세 화면의 `대여 절차`가 이를 보완한다.

### 2.4 `/items/:id` — 물품 상세

**목적** 물품 정보 확인 + 대여/예약 신청. **접근** 로그인. **셸** 헤더+푸터.

**데스크톱 레이아웃 (1024px 이상)**

```
[← 목록으로]                                         [수정] ← 관리자만
┌ 갤러리 1.05fr ─────────────┐   ┌ 정보 0.95fr (최소 320px) ──────┐
│ ┌ 4:3 큰 사진 ──────────┐  │   │ 물품 이름        [● 대여 가능 2개] │
│ │                       │  │   │ 설명 (줄바꿈 유지)               │
│ │                 1 / 3 │  │   │ #분류 #분류                      │
│ └───────────────────────┘  │   │ ── 라벨 ─────────── 값 ──        │
│ [썸네일][썸네일][썸네일]     │   │ 대여 가능  2개                    │
└────────────────────────────┘   │ 전체 보유  3개                    │
                                 │ 보관 위치  7층 비품실              │
                                 │ ┌ 대여 신청 카드 ──────────────┐ │
                                 │ │ 신청 수량        [- 1 +]      │ │
                                 │ │ 지금 대여 1개 / 예약 0개       │ │
                                 │ │ 반납 예정일 [날짜]             │ │
                                 │ │ 메모 * [____________]         │ │
                                 │ │ [        대여하기        ]     │ │
                                 │ └──────────────────────────────┘ │
                                 │ ┌ 대여 절차 1~4 ───────────────┐ │
                                 │ └──────────────────────────────┘ │
                                 └─────────────────────────────────┘
관련 물품 더 보기 — {분류} 물품
[카드][카드][카드][카드]  (모바일 2열, md 4열)
```

- 상단 내비: 왼쪽 `← 목록으로`(검색·필터 쿼리를 유지한 채 홈으로), 오른쪽 관리자만 `수정`.
- 2열 비율 `1.05 : 0.95`, 오른쪽 최소 320px. 모바일에서는 세로 1열(갤러리 → 정보).
- 갤러리: 4:3, 최대 높이 480px, 오른쪽 아래 `1 / 3` 카운터. 사진이 2장 이상이면 3열 썸네일, 선택된 썸네일은 2px 진한 테두리.
- 제목 옆 상태 pill: `대여 가능 N개` / `예약 가능 N개` / `신청 마감` / `수리 중` / `폐기`. 상태별 색.
- 설명은 줄바꿈 유지, 분류는 `#태그` pill 목록.
- 수량 정보는 라벨/값 목록(첫 행 굵게): 대여 가능, (0이면) 예약 가능, 승인 대기, 예약 대기, 전체 보유, 수리 중, 보관 위치.
- 대여 폼 상태:
  - 사용자 확인 중 → `사용자 확인 중…` 안내.
  - 비로그인 → `대여하려면 로그인이 필요합니다` + 로그인 버튼.
  - 폐기 → `더 이상 대여하지 않는 물품입니다`.
  - 재고·대기열 모두 마감 → `지금은 대여도 예약도 마감되었습니다`.
  - 소모품 → 폼 대신 `소모품입니다 — 관리자에게 문의` 안내.
  - 대여 가능 → 제목 `대여 신청`, 수량 스테퍼, 지금/예약 분리 표시, 반납일, 메모, `대여하기`.
  - 재고 0·예약 가능 → 제목 `예약 신청`, 예약 안내, 반납일 없음, `예약하기`.
- 신청 성공 시 폼이 **성공 카드**로 바뀐다: 체크 원, `대여를 신청했습니다`(또는 예약/복합), 접수 내용·희망 반납일·진행 상황 안내, `대여 내역`/`계속 둘러보기` 버튼.
- 폼 아래 `대여 절차` 카드: 1 물품 선택 → 2 신청서 작성 → 3 승인 → 4 반납. 번호 원 + 굵은 단계명 + 설명.
- 관련 물품: 같은 첫 분류의 다른 물품 최대 4개. `전체 보기` 링크.
- 로딩: 갤러리·정보 자리에 스켈레톤. 오류: `다시 시도` + `목록으로` 빈 상태.

**검토 포인트**

- 데스크톱에서 대여 폼이 오른쪽 컬럼의 상당 부분을 차지한다. 첫 화면(스크롤 없이)에서 CTA가 보이는지, 사진이 너무 커서 정보가 밀리지 않는지.
- 모바일에서 갤러리(4:3) 다음에 제목·상태·설명·수량 목록을 지나야 폼이 나온다. 신청까지 스크롤이 길지 않은지.
- 수량 스테퍼 + “지금/예약” 분리 + 반납일 + 메모가 한 카드에 들어가 있다. 처음 쓰는 회원에게 한 번에 너무 많은 결정을 요구하지 않는지.
- 성공 카드로 교체되면 폼이 사라져 “추가 신청”이 불가능하다. 의도된 흐름인지.

### 2.5 `/mypage` — 내 정보

**목적** 계정 정보 확인·수정, 필수 정보 미등록 안내. **접근** 로그인. **셸** 헤더+푸터.

**데스크톱 레이아웃**

```
내 정보
계정 정보와 연락처를 관리합니다.
┌ 필수 정보 배너 (연락처/소속 없을 때) ────────────────┐
│ 물품을 대여하려면 ... 등록해야 합니다.   정보 등록하기 │
└──────────────────────────────────────────────────────┘
┌ main 1fr ───────────────────────────┐ ┌ aside 320px sticky ┐
│ 계정 정보                            │ │ 대여 현황           │
│ ┌ 카드 ────────────────────────────┐ │ │ ... [대여 내역 보기]│
│ │ (이니셜) 이름            [수정]   │ │ ├ 연락처 안내 ──────┤
│ │          정토회                   │ │ │ ...                │
│ │ ── 이메일 ────────── user@... ──  │ │ └────────────────────┘
│ │ ── 연락처 ────────── 010-... ──   │ │
│ │ ── 소속 ───────── 지부·지회·모둠 ── │ │
│ │ ✓ 저장했습니다 (저장 직후)         │ │
│ └──────────────────────────────────┘ │
└─────────────────────────────────────┘
```

- 상단 배너: 연락처가 없거나 지부·지회·모둠이 유효하지 않으면 연한 오렌지 면 + `정보 등록하기` 텍스트 버튼.
- 계정 카드: 48px 이니셜 아바타, 이름(없으면 이메일), `정토회`, 우측 `수정` 버튼. 그 아래 구분선 있는 라벨/값 목록(이메일·연락처·소속).
- `수정`을 누르면 같은 카드 자리가 **인라인 수정 폼**으로 바뀐다: 아바타 + `계정 정보 수정` + `이메일은 변경할 수 없습니다` + 이메일 칩 + 이름/휴대폰/지부/지회/모둠 + `취소`/`저장`. 저장하면 다시 보기 모드로 돌아오고 `✓ 저장했습니다`.
- 우측 패널: `대여 현황` 카드(대여 내역 링크) + `연락처 안내` 카드. 1024px 미만에서는 숨김.
- 로딩: 카드·우측 패널 스켈레톤.

**검토 포인트** 정보가 적은 화면인데 2열 셸을 써서 오른쪽이 비어 보일 수 있다. 인라인 편집 전환과 `수정` 버튼 위치가 명확한지.

### 2.6 `/my/rentals` — 대여 내역

**데스크톱 레이아웃**

```
대여 내역
신청한 물품의 승인 상태와 지난 기록을 확인합니다.
```

- 섹션 순서: **승인 대기 → 예약 대기 → 현재 대여 중 → 대여 이력(접이식)**. 각 섹션 제목 20px + 14px 설명.
- 승인 대기·예약 대기 섹션은 해당 건이 있을 때만 보인다. 현재 대여 중은 항상 보이고, 비었으면 안내 카드 + `물품 둘러보기`.
- 행(`ReservationRow`): 흰 카드, 16px 패딩, 제목 `물품명 · N개` + 상태 배지 + 우측 액션. 아래 14px 회색 메타 줄들. 대여 중 행은 진한 테두리.
- 모바일에서 액션 버튼은 다음 줄로 내려가 폭을 나눠 갖는다(반납/취소 2개가 나란히).
- 예약 대기 행은 `앞에 N개 대기 중` 또는 `다음 순번입니다`를 보여준다.
- 반납하기 → 520px 모달: 물품명·수량, `물품 상태 사진 (선택)`, 사진 3열 업로더(최대 3장), `사진은 본인과 관리자만`, `취소`/`반납 완료`. 업로드 실패 시 `사진 없이 반납` 대안 버튼.
- 취소 → 확인 모달: 예약이면 “대기열에서 빠지며 다시 신청 가능”, 대여면 “대여하지 않은 것으로 기록”. 확인 버튼 `예약 취소`/`대여 취소`.
- 반납 사진이 있으면 행 안에 썸네일 스트립(80px) + 클릭 확대.
- 메시지는 화면 상단 한 줄. 성공은 체크 아이콘, 오류는 빨간 글자.
- 로딩: 헤더 + 좌측 스켈레톤 3행 + 우측 스켈레톤 카드 2개.

**검토 포인트**

- 한 화면에 최대 4개 섹션 + 접이식 이력 + 우측 안내 2개. 정보량이 많은 편인데 스캔 순서가 자연스러운지.
- “승인 대기”와 “예약 대기”가 실제로는 같은 신청 흐름인데 섹션이 나뉘어 있어, 처음 보는 회원이 둘의 차이를 이해할 수 있는지.
- 우측 안내 패널이 모바일에서 사라져 반납 규칙을 알 수 없다. 행 안의 설명만으로 충분한지.
- 액션 버튼이 `반납하기`(primary)와 `취소`(secondary)로 붙어 있어 실수로 취소할 위험이 없는지.

### 2.7 `/admin/reservations` — 대여 관리

**목적** 전체 신청을 상태별로 보고 승인·거절·반납 처리. **접근** 관리자. **셸** 헤더+푸터.

**데스크톱 레이아웃**

```
대여 관리
신청을 승인·거절하고 대여·반납 상태를 확인합니다.
✓ 처리 메시지

[전체][승인 대기][예약 대기][대여 중][기한 지남][반납 완료][취소][거절]
┌ main 1fr ──────────────────────────────────┐ ┌ aside 320px ─────────┐
│ ┌ [물품 · 1개] [승인 대기]   [승인][거절] ──┐│ │ 반납 처리 안내        │
│ │ 김회원 · 소속 · 010-...                    ││ │ 승인/거절/반납 규칙... │
│ │ 재고 2 · 대여 중 1 · 승인 대기 1 · 예약 0 ││ └──────────────────────┘
│ │ 2026-11-05 대여 · 반납 예정 11-07        ││
│ │ 메모 · ... / 반납 사진 [썸네일]           ││
│ └───────────────────────────────────────────┘│
│ ┌ [물품 · 1개] [대여 중]            [반납] ──┐│
│ │ 회원 · 소속 · 연락처                      ││
│ │ 2026-11-01 대여 · 반납 예정 ...           ││
│ │ 회원이 직접 반납했습니다 — 회수 확인 필요  ││
│ └───────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
```

- 상단 필터 칩 8개: `전체 / 승인 대기 / 예약 대기 / 대여 중 / 기한 지남 / 반납 완료 / 취소 / 거절`. URL `?status=`와 동기화.
- 각 행은 `inlineActions` 모드: 모바일에서도 제목이 말줄임되고 액션은 오른쪽에 유지된다.
- 승인 대기·예약 대기 행: `승인`(primary) + `거절`(danger) 버튼. 예약 대기인데 재고가 없으면 `승인` 비활성 + 빨간 `재고가 없어 승인할 수 없습니다`.
- 대여 중 행: `반납`(secondary).
- 행 메타데이터(밀도 높음): 회원 이름 · 소속 · 전화(전화 링크) 또는 이메일 → 재고/대여 중/승인 대기/예약 대기 수치 → 예약 순번·승인 가능 여부 → 신청일 → 반납 예정일(지나면 빨강) → 거절 사유 → 처리자·처리일 → `회원이 직접 반납했습니다` 경고 → 메모 → 반납 사진(회원/관리자 구분).
- 500건까지만 표시되면 상단에 `500건까지만 표시 — 더 오래된 건은 여기 없습니다`.
- 승인 클릭 → 420px 모달: 물품/수량 설명, 예약 건이면 예약 안내, `반납 예정일 *` 날짜 입력(내일~30일), 도움말, 오류, `닫기`/`승인`.
- 거절 클릭 → 420px 모달: `거절 사유 *` textarea(예시 placeholder), 사유는 회원 이력에 남는다는 안내, `닫기`/`거절`(빨강).
- 반납 클릭 → 회원과 같은 반납 모달(관리자 모드, 회수 확인 사진).
- 로딩: 행 스켈레톤 4개. 오류: compact 오류 + `다시 시도`.

**검토 포인트**

- 한 행에 최대 8줄의 메타데이터가 쌓인다. 관리자가 “승인할 건”을 빠르게 찾는 화면인데 정보 밀도가 지나치지 않은지.
- 승인·거절이 행 안에 바로 있어 오조작 위험이 있는지. 승인은 날짜 모달을 거치지만 거절은 사유 입력 모달을 거친다.
- 필터 8개가 한 줄에 다 들어가지 않으면 줄바꿈된다. 모바일에서 필터 탐색이 피로하지 않은지.
- `기한 지남`이 상태가 아니라 `대여 중 + is_overdue` 파생 필터라는 점이 UI에서 자연스럽게 읽히는지.

### 2.8 `/admin/members` — 회원 관리

**목적** 회원 역할 변경·탈퇴·등록 정보 삭제, 로그인 허용 이메일 관리. **접근** 관리자. **셸** 헤더+푸터.

**데스크톱 레이아웃**

```
회원 관리
회원 역할과 로그인 허용 이메일을 관리합니다.
✓ 메시지

[이름, 이메일, 연락처 검색… 🔍]
┌ main 1fr ──────────────────────────────────┐ ┌ aside 320px ─────────┐
│ ┌ 회원 카드 ──────────────────────────────┐ │ │ 역할 안내             │
│ │ (이니셜) 김회원 [탈퇴]   [회원 ⌄] [탈퇴] │ │ │ 회원/관리자 설명...    │
│ │          kim@... · 010-...              │ │ ├ 마지막 관리자 보호 ───┤
│ │          소속: 지부·지회·모둠              │ │ │ ...                   │
│ └─────────────────────────────────────────┘ │ └───────────────────────┘
│ ┌ 회원 카드 ... ───────────────────────────┐ │
│ └─────────────────────────────────────────┘ │
│ ▸ 로그인 허용 이메일 (접이식)                │
│   [이메일] [메모(선택)] [추가]               │
│   ┌ email · 메모 · 등록자 · 날짜   [제거] ─┐ │
│   └────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

- 검색: 이름·이메일·연락처 부분 일치, 즉시 필터(서버 요청 없음). `Esc`로 지우기.
- 회원 카드: 36px 이니셜 아바타, 이름(없으면 `—`), 탈퇴 배지, 이메일 · 전화(전화 링크), `소속: ...`. 우측에 역할 select(회원/관리자) + `탈퇴`(danger). 탈퇴 회원은 select 대신 `등록 정보 삭제` 버튼.
- 모바일: 액션 영역이 카드 아래 전체 폭으로 내려가고, select와 버튼이 폭을 나눈다.
- 마지막 관리자는 역할 변경·탈퇴 버튼이 비활성되고 툴팁으로 이유를 보여준다.
- 대여 중인 탈퇴 회원은 등록 정보 삭제가 비활성되고 `대여 중 N건 · 반납 또는 취소 처리가 필요합니다` 안내.
- 확인 모달: 탈퇴(세션 종료·재로그인 시 복구·역할 초기화), 등록 정보 삭제(개인정보 제거·이력 익명 보존·되돌릴 수 없음).
- 로그인 허용 이메일: 접이식 `<details>`. 펼치면 이메일/메모 입력 + `추가`(3열, 720px 이상), 아래에 등록 목록(이메일·메모·등록자·날짜 + `제거`). 목록은 흰 카드에 행 구분선.
- 로딩: 회원 카드 스켈레톤 4개 + 허용 이메일 스켈레톤. 오류: compact + `다시 시도`.

**검토 포인트**

- 카드형 행이 세로로 길어 회원이 많아지면 스캔이 느려진다. 표 형태가 나은지.
- 역할 select와 `탈퇴`가 같은 줄에 있어 파괴적 동작이 일상 동작 옆에 붙어 있는 점.
- 허용 이메일 관리가 접이식으로 숨겨져 있어 “로그인 문제”를 해결하려는 관리자가 찾기 어려운지.

### 2.9 `/items/new` · `/items/:id/edit` — 물품 등록·수정

**목적** 물품 정보·재고·사진 등록/수정, 수정 화면은 삭제도. **접근** 관리자. **셸** 헤더+푸터.

**데스크톱 레이아웃**

```
물품 등록 (또는 물품 수정)              [취소] [저장]
새 물품의 정보와 사진을 등록합니다.
┌ main 1fr ──────────────────────────────────┐ ┌ aside 320px ─────────┐
│ ⚠ 오류 배너 (있을 때)                       │ │ 작성 안내             │
│ ┌ 기본 정보 ─────────────────────────────┐ │ │ 이름·수량 필수...      │
│ │ 이름 * / 보관 위치 / 설명(textarea)     │ │ ├ 사진 안내 ───────────┤
│ └─────────────────────────────────────────┘ │ │ 최대 3장, 첫 장 대표   │
│ ┌ 분류 · 상태 ───────────────────────────┐ │ └───────────────────────┘
│ │ 카테고리 태그 입력                       │ │
│ │ [대여품|소모품]  [사용|폐기]             │ │
│ └─────────────────────────────────────────┘ │
│ ┌ 재고 ──────────────────────────────────┐ │
│ │ [보유 수량 *] [수리 중 수량]             │ │
│ │ 도움말 2줄                              │ │
│ └─────────────────────────────────────────┘ │
│ ┌ 사진 ──────────────────────────────────┐ │
│ │ [사진][사진][+ 추가]  3 / 3             │ │
│ │ 형식·용량·자동 축소 안내                 │ │
│ └─────────────────────────────────────────┘ │
│ ┌ 위험 영역 (수정만) ────────────────────┐ │
│ │ 삭제 경고 ...              [물품 삭제]  │ │
│ └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

- 페이지 제목 우측에 `취소`(secondary) + `저장`(primary, form 밖에서 `form="item-form"`으로 제출). 저장 중 로딩, 사진 처리 중 비활성.
- 섹션은 모두 흰 카드(24px 패딩, 모바일 16px). 섹션 제목 20px.
- 기본 정보: 이름 *, 보관 위치(예: 7층 비품실), 설명 textarea 3행.
- 분류·상태: 카테고리 태그 입력(엔터/쉼표로 추가, Backspace로 마지막 제거, 기존 카테고리 datalist 제안, 한글 IME 조합 처리) + `구분` 칩(대여품/소모품) + `상태` 칩(사용/폐기).
- 재고: 보유 수량 *, 대여품일 때만 수리 중 수량. 도움말: 수리 중은 대여 불가, 보유 수량을 넘을 수 없음, 대여 중·수리 중보다 적게 줄일 수 없음.
- 사진: 3열 업로더, 최대 3장, 첫 장 `대표`. 추가/삭제는 저장 시 서버 반영. 업로드 전 2MB 이하 자동 축소.
- 위험 영역: 수정 화면에만. `물품 삭제`(danger) → 확인 모달 → 삭제 후 홈으로.
- 변경 사항이 있는 상태에서 취소/뒤로가기/새로고침 시 확인 모달·브라우저 경고.
- 저장 성공 시 물품 상세로 이동. 사진만 실패하면 “물품은 저장되었습니다. 사진 처리만 실패…” 오류 배너.
- 로딩: 섹션 모양을 닮은 스켈레톤.

**검토 포인트** 폼이 4~5개 카드로 세로로 길다. 필수/선택 구분이 라벨의 `*` 하나뿐인 점, 저장 버튼이 상단에만 있는 점(긴 폼에서 하단 저장이 필요한지), 위험 영역이 폼 맨 끝에 있는 점.

### 2.10 `/policy/terms` · `/policy/privacy` — 정책 문서

**목적** 약관·개인정보 처리방침 열람. **접근** 공개. **셸** 헤더+푸터.

**데스크톱 레이아웃**

```
[이용약관] [개인정보 처리방침]   ← 밑줄 탭
[페이지 제목]                     ← PageHeader
┌ 본문 680px ────────────────────┐   ┌ 목차 320px (sticky) ──┐
│ 개인정보 처리방침               │   │ 목차                   │
│                                │   │ 수집 항목               │
│ 1. 수집하는 개인정보 항목       │   │ 수집 목적               │
│  · 구글 계정 정보 ...           │   │ ...                    │
│ 2. 수집 목적                    │   │ 문의처                  │
│  · ...                         │   └────────────────────────┘
│ [표] (좁은 화면 가로 스크롤)     │
│ ...                            │
│ 시행일: 2026-11-02              │
└────────────────────────────────┘
```

- 최대 1280px 셸, 본문 680px + 목차 320px. 목차는 `order`로 오른쪽에 두고 sticky.
- 상단에 탭 2개(`이용약관` / `개인정보 처리방침`)를 두고, 그 아래 `PageHeader`에 문서 제목을 둔다. 활성 탭은 진한 글자 + 2px 밑줄.
- 탭·문서 제목·브라우저 제목·푸터 링크 이름은 모두 같은 말(`이용약관`, `개인정보 처리방침`)을 쓴다.
- 본문: h2 20px(스크롤 오프셋 96px), 본문 14px/1.5, 목록 disc, 표는 14px·테두리·가로 스크롤. 본문은 h2부터 시작하고 h1은 `PageHeader`가 맡는다.
- 목차 링크는 부드러운 스크롤. 모바일에서는 목차를 **숨긴다**.
- 표가 화면보다 넓으면 `표는 좌우로 넘겨서 볼 수 있습니다` 안내(모바일).
- 시행일은 문서 내용의 마지막 문단으로 둔다.
- 각 문서 7개 섹션. 개인정보: 수집 항목/목적/보관·파기/제3자 제공/위탁/회원 권리/문의처. 약관: 목적/가입/대여/회원 의무/운영진 의무/책임 제한/변경.

**검토 포인트** 모바일에서 목차가 사라져 긴 문서를 탐색하기 어려운지. 문서 폭 680px과 표의 가로 스크롤이 답답하지 않은지.

## 4. 정보 구조 & 내비게이션 요약

```
로그인 /login
   └─(첫 로그인, 연락처 없음)→ /signup/profile → /mypage
홈 / (물품 현황)
   ├─ 물품 상세 /items/:id ──(관리자)→ /items/:id/edit
   ├─ (관리자) /items/new
   ├─ 대여 내역 /my/rentals
   └─ (관리자) /admin/reservations, /admin/members
내 정보 /mypage
정책 /policy/terms, /policy/privacy (푸터·로그인·프로필에서 진입)
404
```

- 헤더 주 메뉴는 역할에 따라 달라진다. 회원: `물품 현황 · 대여 내역`. 관리자: `물품 현황 · 대여 관리 · 회원 관리 · 대여 내역`.
- `내 정보`는 헤더 계정 드롭다운에만 있다(주 메뉴에는 없음).
- 관리자 전용 화면을 회원이 열면 `/?role=denied`로 보내고 홈 상단에 빨간 권한 안내를 띄운다.
- 연락처·지부·지회·모둠이 없으면 역할과 무관하게 `/signup/profile`로 보낸다.

## 5. 접근성·인터랙션 메모

- 모든 인터랙티브 요소에 `:focus-visible` 2px 아웃라인. 색만으로 상태를 구분하지 않도록 점·텍스트·아이콘을 병행.
- 버튼·입력 높이 40px, 칩 36px, 모바일 FAB 48px. 터치 타깃은 대체로 40px 이상.
- 아이콘 전용 버튼은 `aria-label`(검색 지우기, 사진 삭제, 수량 증감 등).
- 필터 칩은 `role=group` + `aria-pressed`, 탭형 링크는 `aria-current=page`.
- 목록은 `role=list`/`listitem`, 로딩·빈·오류는 `role=status`/`alert`.
- 이미지 `alt`: 물품 사진은 이름 기반, 썸네일은 빈 alt(장식), 반납 사진은 “반납 사진 N”.
- `prefers-reduced-motion`이면 애니메이션을 거의 끈다.
- 스크롤 위치 복원: 목록↔상세를 오가면 이전 스크롤 위치를 복원한다.

## 6. 알려진 제약·검토 가설 (리뷰어에게 참고)

> 아래는 “정답”이 아니라 현재 구현의 특성이다. 리뷰에서 동의/반박해도 된다.

1. **우측 320px 보조 패널이 5개 화면(홈·내 정보·대여 내역·관리자 2개)에 반복**된다. 데스크톱에서는 안내를 제공하지만, 모바일에서는 전부 사라져 동일한 정보가 유실된다.
2. **관리자 화면의 행 정보 밀도가 높다.** 특히 대여 관리는 한 행에 8줄까지 쌓인다.
3. **홈의 검색 폭(400px)과 그리드 폭(전체)** 이 서로 다른 리듬을 만든다.
4. **대여 내역이 4개 섹션 + 접이식 이력**이라 세로 길이가 길다.
5. **상세 화면 CTA가 오른쪽 컬럼 아래쪽**에 있어, 모바일에서는 여러 정보를 지나야 신청할 수 있다.
6. **로그인/프로필 등록만 헤더가 없다.** 온보딩 맥락이 약할 수 있다.
7. **정책 문서 모바일 목차 없음.**
8. **관리자 회원 관리가 카드형**이라 회원 수가 많을 때 표보다 느릴 수 있다.
9. **파괴적 액션(탈퇴·삭제)이 일상 액션 옆**에 같은 크기로 있다.
10. **다크 모드 없음**, 라이트 모드 고정.

## 7. 리뷰에서 답해줬으면 하는 것

- 화면별 **정보 계층**(무엇을 먼저 읽게 되는가)과 **주 액션 도달 거리**.
- 데스크톱 2열 셸(본문 + 320px 안내)의 유지/변형/제거 판단.
- 모바일에서 사라지는 보조 정보의 대안(인라인 요약, 접이식, 하단 시트 등).
- 관리자 목록의 **스캔 효율**(행 vs 표, 필터 위치, 액션 배치).
- 폼(대여 신청, 물품 등록)의 **결정 피로**와 단계 분리 필요성.
- 우선순위가 높은 개선안 **P0/P1/P2**와, 유지해야 할 강점.
